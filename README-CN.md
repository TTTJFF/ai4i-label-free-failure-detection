# 基于支撑边界越界评分的无标签机械故障检测

*AI4I 2020 基准上的受控消融实验*

在 AI4I 2020 预测性维护数据集上，有监督模型的最好成绩是 F1 **0.692**，而三种标准无监督检测器中最好的只有 **0.203**。这个差距通常被解释为无监督方法本身的局限。本仓库要说明的是：在这份数据上，它来自**训练开始之前就已做出的两个选择**——检测器看到的是哪些坐标，以及要求它给什么打分。只改这两件事，零标签 F1 从 **0.203** 升到 **0.463**（十个分层划分上的标准差 ± 0.032），报警预算保持不变，且没有任何标签参与拟合、选型或阈值确定。

---

## 结果一览

| 零标签配置 | F1 | PR-AUC |
|---|---|---|
| 原始传感器特征上的稀有度打分 —— 单类 SVM | 0.203 | 0.168 |
| ＋三个派生坐标（功率、温差、磨损×扭矩）—— 孤立森林 | 0.244 | 0.185 |
| ＋把"稀有度"换成"支撑边界越界程度"—— 报警预算固定 3.39 % | 0.383 | 0.424 |
| ＋最终子空间池 —— 十个划分的均值与标准差 | **0.463 ± 0.032** | **0.516** |
| 有监督上界（MLP，用 339 条故障样本训练） | 0.692 | 0.747 |

前两行取该表征下三种标准检测器中的最好者，后两行是支撑越界检测器在固定报警预算下的结果。每一行只改**一件**事——特征、打分、阈值从不一起动，增益才能归因。同一个坐标改动，不同检测器族的响应差别很大：孤立森林 **+0.105**、LOF **+0.047**、单类 SVM **+0.005**——后者的 RBF 核本来就会绕着乘积约束弯过去。

操作点上的后果（按漏检代价 1,000、点检代价 100 计）：

| 策略 | 期望代价 |
|---|---|
| 永不报警 | 102,000 |
| 已发布管线，单一阈值 | 67,500 |
| 单一阈值＋观察名单前 20 %（召回 0.735） | 43,580 |

最后一行只在"被监控的故障最终会被抓到"的概率 α ≥ 0.68 时成立。该条件与数字同时给出，而不是放在数字之后。

## 快速开始

```bash
git clone <本仓库地址>.git && cd <仓库目录>
pip install -r code/requirements.txt        # 6 个依赖，无需 GPU

cd code
python scripts/eda.py                       # 数据体检：10,000 × 14，无缺失值
python scripts/run_experiments.py           # 任务 A / B / C：5 + 4 + 3 个模型、代价与阈值曲线
python "unsupervised learning/step2/run_step2.py"   # 上文那张受控消融表
```

完整流程共八个脚本，顺序、输出与预期数值见 [`code/README.md`](code/README.md)。普通笔记本 CPU 上 **3–8 分钟**跑完。所有随机过程使用固定种子，指标可逐位复现，只有训练耗时列随机器负载浮动。

## 两个改动

**一、坐标。** 五种失效模式里有三种是派生量的确定性函数：机械功率落到区间之外、低转速下过程温度与空气温度之差低于阈值、扭矩与累计刀具磨损的乘积超过按机型设定的阈值。这些是用发布数据逐条核对的，而不是照文档抄——三条规则都做到了"零误报、不漏一条"。在原始坐标里，功率约束是一条双曲线；把乘积作为单独一列交出去，一次轴对齐切分就够了。

**二、打分。** 故障落在正常云团**内部**，所以"稀有"是错的问题。改为让检测器回答"这条记录离正常数据的支撑有多远"，该量对越界程度单调，因而可以被阈值切开。

哪个检测器最好取决于坐标：原始特征上单类 SVM 领先，乘积显式化之后孤立森林领先。同一个坐标改动在不同检测器族之间的响应差近二十倍，这正是本仓库在**固定表征内**比较检测器、而不跨表征排名的原因。

下表只统计**真正跑过并落盘**的方法，每一行都能在 `code/**/results*.csv` 里找到对应记录，不包含任何只停留在设想阶段的方法。

| 不平衡处理 | **4 × 3** | 不做处理 / class_weight / 随机过采样 / SMOTE，分别配决策树、随机森林、MLP |

| 特征集 | **3** | F1_raw、F2_physics、F3_physics_pt |

## 复现口径

- 标签只用于**评估**，不参与拟合、选型或阈值确定。唯一的例外是一条被单独报告的分支（L2）：花 300 条标签校准阈值，买到的是操作点（F1 0.383 → 0.435），排序完全没动（PR-AUC 前后都是 0.424）。
- 所有比较在十个分层划分上成对进行，用 Wilcoxon 符号秩检验。判定"提升"需要同时满足 p < 0.05、均值差大于 0.02、**且** PR-AUC 同向；否则一律写"未建立"。
- 27 个结果 CSV 已随仓库提交，不运行代码也能核对每一个数字。
